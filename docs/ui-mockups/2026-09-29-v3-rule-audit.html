规则是我自己在案例墙里写的，所以这次只算 v3 欠了多少，不算它做对了多少。 第 05 条（归属用边框）按小森要求跳过。

一屏对账

「证据」列全部是 v3 源码里的实际数字，不是我对着图看出来的。

规则判定证据（v3 源码实测）
01 一格只放两行文字 达成 13 行会话，每行 4 个文字元素（名字 / 预览 / 时间 / 未读数字）—— 比 WhatsApp 的 5 个还少一个。itemH=58px
02 第三行的价码 达成 第三行整行不存在，代价 0。渠道改由头像角上的色点承担（转给规则 04）
03 未读三选一 选多了 同时用了两种：数字 pill（17px / 10.5px 字）+ 字重提亮（font-weight:660;color:#fff）
04 状态用图形 半落地 会话行 13/13 有图形 ✓，左栏 5 行有图形 ✓；但「需要你处理」6 个 tag 全是纯文字，统计条 4 个徽标里 3 个是纯文字状态
05 归属用边框 跳过 按小森要求不做。理由记一笔：v3 的会话行没有「归属」这个维度，硬加边框只会多一个要解释的记号
06 分隔线缩进，不用卡片框 达成 会话行分隔线 0 条；待处理卡用缩进 hairline（left:12px;right:12px）；白面板从 v2 的 8 个降到 4 个
07 按状态组织，不按对象 未落地 顶栏 5 项全是对象（工作台 / 收件箱 / 联系人 / 模板 / 渠道）；左栏 5 行是渠道筛选 —— 而渠道已经画在 13 行的色点上了
08 密度让人选，窄屏收入口 未落地 @media 出现 0 次；左栏 width:290px 写死；没有第二档密度

逐条说清

每张卡：规则原文 → v3 里的事实 → 判定 → 该动什么。

01

一格只放两行文字

达成

七家的行高都在 60–76px，全部是「名称 + 预览」两行。

元素4 个 / 行 —— 名字、预览、时间、未读数字（13 行无一例外）
行高58px，比七家的下限 60px 还低 2px
头像36px，参照里是 46–48px
判定 做到，而且走得比七家都远。代价要说清：36px 头像 + 58px 行是没有先例背书的一档 —— 七家没人这么做，可能是他们试过觉得挤。要留着，就得拿真数据验一次「点击热区够不够、13px 名字会不会看不清」， 不能只凭截图好看。
02

第三行的价码：+10px、10px 字

达成

Telegram 源码里唯一带第三行的形态是 taggedDialogRow：62 → 72px，标签 10px，且只在必要时出现。

现状第三行整行不存在 —— 不是付了 10px，是不付
替代渠道改成头像角上的色点（.av .ch，13 处全有）
回收v2 付的 20px 行高 + 11.5px 字号，全部退回
判定 这是八条里兑现得最干净的一条。唯一要盯的是它的前置：色点这套要在真项目里成立， 前提是「一个联系人可能有两个渠道」这件事在数据上真的常见 —— 否则角上那个点会有一半是空的。
03

未读三选一，不写「N 条未读」

选多了

数字 pill / 圆点 / 只说字重。没有一家用句子解释未读。

v3 用了数字 pill + 字重提亮 —— 两条同时上
理由数字已经说清「有几条」，加粗是把同一件事说第二遍
对照Telegram 是 12px bold / 19px 高；v3 是 10.5px / 17px，偏小
该动什么（二选一） 要么去掉字重提亮（只留数字 pill，Slack 那一路）； 要么去掉数字、改成圆点（iMessage 那一路）。 我倾向留数字去字重 —— 但顺带把 pill 字号从 10.5 抬到 11.5：10.5px 是 Telegram 给「第三行标签」的字号， 用在未读计数上太小。
04

状态用图形，不用文字

半落地

4 家独立撞到同一做法：色条 / 色点 / 边框承担状态，文字只用来写内容。

做到的会话行 13/13 有渠道色点；左栏 5 行 + 统计条 + 图例都是小色块；选中项是 2.5px 白条
没做到「需要你处理」里 6 个 tag 全是文字（邮件 / 企业微信 / 电话 / 等 14 小时 / 来电未接…）
没做到同一个「渠道」维度，左栏用纯色点、卡片里退回「色点 + 文字」
该动什么 卡片里「渠道」不必带文字 —— 上面那条色点已经教过用户了（同一屏不需要教两遍）。 「紧迫度」（等 14 小时 / 今天 / 逾期）目前一个图形都没有，全是文字： 可以只留颜色（琥珀 / 红）+ 时长数字，把「等」字去掉。
05

归属用边框，不用句子

按要求跳过

Missive 用一条 3px 左边框说「这是团队共享的」，一行字都没写。

处理小森明确说不需要，不落
记一笔v3 的会话行本来就没有「归属」这一维，硬加边框等于多一个要解释的记号 —— 跳过是对的
什么时候再想它 等真项目里出现「这条会话是同事在处理」的诉求时再回来。 Missive 那条的价值不在边框本身，而在「共享」这件事不需要一行字这个思路。
06

分隔线缩进，不用卡片框

达成

微信 / Telegram 的分隔线都从文字起始处开始。一屏能少掉十条横线。

会话行分隔线 0 条，靠 hover 底色 + 圆角分区
待处理用缩进 hairline：left:12px;right:12px
白面板v2 的 8 个 → v3 4 个
判定 达成，是八条里效果最直接的一条。一处遗留：统计条用的是全高贯穿的竖线 （border-left），不是缩进线 —— 规则只谈了横线，竖线这里没规矩，先记着。
07

按「状态」组织，不按「对象」

未落地

Front 的 Open / Later / Done、Slack 的模式 tab —— 两家独立产品给出同一答案。

顶栏5 项全是对象：工作台 / 收件箱 / 联系人 / 模板 / 渠道
左栏5 行是渠道筛选（全部 / 邮件 / 企微 / WhatsApp / 电话）
冲突渠道已经画在 13 行的角上了 —— 筛选维度又占着左栏最贵的位置
该动什么（本批最大改动） 左栏从「渠道筛选」换成状态分组：待我回复 / 等对方 / 已归档（Front 三段直译）。 渠道不删，降级成「挂在列表头上的一排 chips」，或者直接靠色点 —— 因为色点已经是筛选维度了。 顶栏把右上的「待办日历」提上来成一个 tab，让待回复成为一等入口。
08

密度让人选，窄屏收入口不缩字

未落地

Intercom 给了「列表 ↔ 表格」两档；Slack 窗口变窄是把低频 tab 收进 More。缩字号是最差的那种响应式。

断点@media 0 次 —— 一个都没有
布局左栏 width:290px 写死，内容区吃剩下的
密度只有一档，没有紧凑 / 舒适切换
该动什么 先补两个断点就够：≤1280 左栏收到 250px；≤1080 把左栏收成抽屉（按钮展开），内容区优先。 密度切换属于加分项，放后面 —— 一件真在用之前，多一档密度只是多一个没人点的开关。

顺带抓到的两处漏网

这两条不在八条规则里，是这次反扫时撞出来的。

A. 上一轮「13 处小字全清」—— 漏了统计条那 4 个徽标里的 3 个

上一轮我宣称 13 处解释性小字全清（statSub=0 等五组指标全 0）。但那次只审了统计条的第三行 —— 第二行那 4 个 <em> 徽标被我整批当成「环比」放过了。逐个看： 只有「+2 本周」真是环比，其余三个是解释或自证 —— 「需今天处理」与卡片标题的「3」和卡内三条重复（同一件事说了三遍）、 「全部健康」是页面自证、「已完成 2」下方待办列表里本来就能数出来。

这四条里该留 1 条、改 1 条、删 2 条。

B. 同一个「渠道」，v3 教了两遍

v3 把渠道降成色点（规则 04），同时又保留了左栏 5 行渠道筛选（规则 07 的对象组织）。 结果是同一个维度在左栏上方被文字点名一次、在 13 行里被色点画一次。 规则 04 和 07 合起来推的结论是同一个：左栏那五行该让位给状态分组。

这也解释了为什么现在左栏看着"有点空又有点杂"—— 它占着最贵的位置，做的是已经做过的事。

按代价排序，我建议这么动

A 档改完不会动结构；B 档是结构决策，得你先点头。

A · 低风险
三条纯删改：未读去字重、pill 字号 10.5 → 11.5、统计条删 2 改 1 个徽标

都不动布局，改完更干净；规则 03、04 的欠账能还掉一半。

A · 低风险
补两个响应式断点（≤1280 收左栏、≤1080 收抽屉）

@media 现在是 0 次，这是纯粹的欠账，没有取舍问题。

B · 结构
左栏从「渠道筛选」换成「状态分组」（待我回复 / 等对方 / 已归档）

规则 07 的落地，也是这批最有价值的一改。渠道降级成列表头上的 chips。 代价：筛选能力的动线变了，用户得重新学一次。

C · 待定
36px 头像 / 58px 行高要不要留

七家没人这么做。留着更紧凑但没先例，建议拿真数据量一次点击热区再定。
