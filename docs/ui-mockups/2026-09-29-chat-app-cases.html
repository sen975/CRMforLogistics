叠起来看就一句话：会话列表永远是实色那一块、永远在左起第二格； 渠道、文件夹、团队这些「分类」全被塞进它上面或左边的侧栏； 右侧多出来的那一格（Front / Intercom）放的是客户上下文，不是渠道。

最右两列是关键 —— 「第三行」那一列，九家里只有两家有，而且代价写得很清楚。

行高是最贵的那个数字。除 Slack / Linear 那种「行内只有一行文字」的列表，其余七家全部落在 60–76px 之间， 而它们的共同点是行内只有两行文字（名称 + 预览）。
唯一合规的例外是 Telegram：源码里 dialogsRowHeight: 62px，只有当会话带「标签」时才切到 taggedDialogRow: 72px，标签行落在 52px 处、字号 10px —— 它给第三行开的价是「+10px 行高、10px 字号，而且只在必要时出现」。

它做对了什么

默认 62px 只放两行；需要第三行时，它不改字号、不改结构，老老实实把行高加 10px 并在 52px 处放一行 10px 的小标签。 连头像尺寸（46）、名称的纵坐标（10）、预览的纵坐标（34）都是写死的常量。

能抄什么

这是我们最该记的一笔账：如果要保留「渠道」那一行，就按 Telegram 的价码付—— 行高只加 10px、字号降到 10px、且只在信息真的不同时才出现（同一联系人三个渠道都来过才需要标）。 我们上一版给这行付了 20px 行高 + 11.5px 字号、而且每一条都出现。

分隔线左端不贯穿：从文字起始处开始画。零成本买到「分组感」—— 你的眼睛会自然把头像和它的两行字读成一块，而不是读成一整片横线切出来的表格。

它做对了什么

未读是一个圆点，不是数字。在一对一聊天里，「有几条」根本不重要，重要的是「有没有」—— 它把数字这一整类信息从行里删掉了。另外置顶被提到了列表外面（圆头像网格），常用的人不再占列表格子。

能抄什么

我们的未读现在是「有就标、没就空」这一档，但可以更省：一对一客户用点、群 / 工单用数字。 另外「最近聊过的 3 个人」可以学它做成顶部的头像排 —— 这比在列表里给它们加粗更省地方。

它做对了什么

2026 改版把 inbox 拆成 Open（要处理）/ Later（等对方）/ Done（已完结） —— 按「状态」组织，不按「对象」组织。同时把搜索从顶栏搬进左栏、会话头压到 3 行， 只为腾出中间那条纵向空间给列表和正文。

能抄什么

这一条直接就是我们的信息架构答案：我们现在按「渠道」分（邮件 / 企微 / WA / 电话）， 但用户脑子里想的是「谁在等我回」。把「渠道」降成筛选、把「待回复 / 等待中 / 已完」升成主分段， 和 Front 是同一个动作。搜索也不该占顶栏一格。

它做对了什么

它承认同一个 inbox 要服务两种人：一线要「一条一条读」，主管要「一眼看全局」。 于是做了 View 切换（列表 ↔ 表格），而不是折中出一个谁都不好用的中间密度。 另外 ⌘K 让「记忆快捷键」这件事从用户身上挪到了产品身上。

能抄什么

密度应该是用户选的，不是我们猜的。我们的列表可以先给「舒适（两行）」和「紧凑（一行）」两档， 主管那一档直接进表格视图看「等待时长 / 负责渠道 / 状态」。这个比再堆信息有用得多。

它做对了什么

它把「工作模式」提成了顶栏 tab（在家看全部 / 只看私聊 / 只看通知 / 稍后处理）， 而不是让用户在同一个列表里靠筛选器找。并且窗口变窄时不是把字号缩小，是把低频入口收进 More。

能抄什么

我们顶栏现在混装了「渠道」和「功能」。Slack 给的答案是：顶栏只放「模式」 （工作台 / 收件箱 / 联系人 / 模板），渠道沉到左栏做筛选 —— 这和 Front 的路子完全一致， 两家独立产品撞到同一个答案，基本可以当结论用。

04九个案例收敛成八条

左边是它们的做法，右边是我们能直接落的动作。凡是有多家独立撞到同一答案的，都标注了。

01一格只放两行文字

七家的行高都在 60–76px，全部是「名称 + 预览」两行。要第三行就得付代价。

WhatsApp · Telegram · 微信 · iMessage · Front · Intercom · Missive

02第三行的价码：+10px、10px 字

Telegram 源码里唯一带第三行的形态是 taggedDialogRow：62 → 72px，标签 10px， 且只在必要时出现。我们上一版付了 20px + 11.5px，还每条都出现。

Telegram（源码）

03未读三选一，不写「N 条未读」

数字 pill / 圆点 / 只说字重。没有一家用句子解释未读。

WhatsApp 数字 · iMessage 圆点 · Slack 字重

04状态用图形，不用文字

4 家独立撞到同一做法：色条 / 色点 / 边框承担状态，文字只用来写内容。

Linear 2px 条 · iMessage 圆点 · Missive 色条 · 微信角标

05归属用边框，不用句子

Missive 用一条 3px 左边框说「这是团队共享的」，一行字都没写。

Missive

06分隔线缩进，不用卡片框

微信 / Telegram 的分隔线都从文字起始处开始。一屏能少掉十条横线。

微信 · Telegram

07按「状态」组织，不按「对象」

Front 的 Open / Later / Done、Slack 的模式 tab —— 两家独立产品给出同一答案， 而我们的顶栏现在混装了渠道和功能。

Front 三段 · Slack 四 tab

08密度让人选，窄屏收入口不缩字

Intercom 给了「列表 ↔ 表格」两档服务两种人；Slack 窗口变窄是把低频 tab 收进 More。 缩字号是最差的那种响应式。
