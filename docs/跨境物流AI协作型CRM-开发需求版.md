# 跨境物流 AI 协作型 CRM 开发需求版

## 一、方案背景

### 1.1 行业背景

跨境物流公司的业务开发高度依赖员工沟通、客户资料收集、供应商资源匹配和持续跟进。员工在开发客户、维护供应商、对接海外代理时，会同时使用邮箱、WhatsApp、企业微信、电话、线下记录等多个渠道，业务信息天然分散。

传统 CRM 更偏向表单录入和客户资料管理，但跨境物流开发过程更强调“沟通驱动”和“机会推进”。如果系统只要求员工填写客户表单，员工使用意愿会低，数据也难以持续更新。

因此，本项目需要自研一套面向跨境物流场景的 AI 协作型 CRM，把分散沟通沉淀为合作方档案、联系人画像、topic 时间线、跟进任务、背调报告和管理看板。

### 1.2 当前业务痛点

- 员工开发客户缺少清晰规划，容易凭经验推进。
- 客户、供应商、代理和内部协作信息分散在多个渠道。
- 联系人身份识别困难，无法快速判断对方是客户、供应商、代理还是内部人员。
- 员工背调客户和供应商的能力不稳定，难以形成统一开发质量。
- 老板无法实时看到员工开发进度、逾期跟进和高价值机会。
- 问题处理经验留在个人脑子里，难以复用。
- 普通 CRM 表单过重，员工不愿意持续录入。
# 来源
- 我的员工主观能动性不足，在与客户谈订单的时候总是没有合理的规划流程，开发客户规划困难，我希望可以借助ai帮助员工规划开发流程，让员工去选择如何开发；
- 我们做物流谈合作的时候信息非常零散，信息归整不足，一般都会分布在WhatsApp，企业微信，邮箱，电话录音等，而这些信息又会根据对象不一样，如客户的信息，供应商的信息，员工内部的信息等，导致搜集困难，因为信息收集困难的问题又导致了流程没办法规范化，不知道什么时候订单就开始了，也不知道什么时候结束，结果如何，所以我需要ai可以根据WhatsApp账号，wx号，电话号，邮件去识别联系人是谁，是什么身份？是客户还是供应商还是其他，根据身份去分类；
- 我认为公司开发客户的流程不应该是死板的，应该是由员工自己的安排去推进开发客户的进度，因为每个人开发的方式不一样，每个订单的情况也不一样；
- 我作为boss我只想知道结果如何，进度能清楚就可以，我需要ai帮我做好员工的开发流程监控，可以提醒员工跟进开发客户的事务，因为我作为boss不可能每个员工都去督促；
- 我现在的员工在背调客户，供应商的地方是欠缺的，不能很好的根据他们的官网，借助网络搜索去背调客户或者供应商的资料去针对性的开发合作，所以我希望在这部分可以由ai帮忙整理资料，给出合理的开发建议；
- 员工在开发客户的时候可能会遇到一些问题，我希望可以把问题上报保存，希望可以复用解决问题的经验，并且由ai来给员工合理的建议；
- 我希望可以总结合作方人员的画像，用合理的关键字去总结对方的性格，喜好等，并且根据聊天内容，邮件来往里面的更新信息进行合理的更新，并且要根据客户的聊天内容总结一个大的topic，这个topic根据时间线看见进展，如果后续有聊天信息和这个topic相关的话就推进这个topic的进度，并且总结进度；
- 我希望这个系统是极简设计，所有ai总结的部分都可以人工进行修改和完善，因为我希望是ai和员工进行合作开发客户，所有要实现二者方向上面的统一，员工应该可以根据自己的感受去改动这些总结；
- 员工的ai需求其实就是一个秘书ai，帮忙收集对方公司，对方本人的资料，做背调，有问题给出解决建议或者方案，并且提醒员工工作事宜；
- 这个系统应该是一个简单的crm系统但是定制化我以上的内容，这个crm系统应该有基础的客户板块，邮件板块，跟进事务板块，本公司信息板块，订单板块，个人工作台和团队看板，而且我希望可以尽量减少员工在表单输入上面花费的时间，所以尽量减少非必须的表单输入



### 1.3 自研必要性

本系统不是普通 CRM 的轻微改造，而是围绕跨境物流业务开发流程做定制：

- 以“合作方”统一承载客户、供应商、代理、内部对象和未知对象。
- 以“沟通中心”统一承接邮箱、WhatsApp、企业微信、电话纪要和手动导入内容。
- 以“topic 时间线”沉淀业务推进过程。
- 以“AI 秘书”减少员工整理、判断和提醒成本。
- 以“人工确认机制”保证 AI 建议可控、可信、可追溯。

## 二、建设目标

### 2.1 总体目标

建设一套跨境物流 AI 协作型 CRM，实现“沟通进入系统、AI 自动整理、员工确认推进、老板看到进度”的业务闭环。

### 2.2 一期建设目标

一期优先完成以下目标：

1. 员工可以统一管理合作方和联系人。
2. 邮件、WhatsApp/企微导入记录、电话纪要可以进入沟通中心。
3. AI 可以识别联系人、合作方身份、沟通摘要和 topic。
4. 员工可以确认、修改或拒绝 AI 建议。
5. 系统可以根据沟通生成下一步任务和阶段推进建议。
6. 员工可以在个人工作台处理待办、逾期和待确认事项。
7. 老板和主管可以通过团队看板查看开发进度、逾期任务和关键风险。

### 2.3 一期不建设内容

一期不承诺以下内容：

- 电话录音自动转写。
- 电话号自动识别并归档。
- 自动代替员工发送 WhatsApp、企业微信或邮件。
- 完整订单系统、财务系统、账单系统、运单系统、TMS、WMS。
- 工商、司法、信用黑名单等重风控背调。
- 复杂 BI 和自定义报表。
- 复杂报价引擎。

### 2.4 一期成功标准

一期上线后，至少应满足：

- 员工能在系统内看到自己的合作方、联系人、待办和 AI 建议。
- 至少一种企业邮箱可以同步进入系统。
- WhatsApp 和企业微信至少支持手动导入，并预留 API 接入结构。
- 电话纪要可手动录入，并由员工指定对方联系人。
- 沟通记录可以关联合作方、联系人和 topic。
- AI 建议必须可确认、可修改、可拒绝。
- 老板能通过看板看到基本进度和逾期风险。

## 三、系统整体业务流程

### 3.1 主业务闭环

1. 员工创建合作方，或系统从沟通信息中识别合作方。
2. 邮箱自动同步邮件，员工手动导入 WhatsApp/企业微信聊天记录，员工手动录入电话纪要。
3. 沟通内容进入沟通中心。
4. AI 判断联系人是谁、属于哪个合作方、是什么身份。
5. 员工确认或修改 AI 识别结果。
6. AI 生成沟通摘要，提取物流业务要素。
7. AI 判断该沟通是否关联已有 topic。
8. 员工确认创建或更新 topic。
9. AI 根据沟通内容生成下一步任务和阶段推进建议。
10. 员工确认、修改或拒绝 AI 建议。
11. 个人工作台展示今日待办、逾期任务和待确认建议。
12. 团队看板展示合作方进度、topic 活跃度、员工跟进情况和风险。

### 3.2 信息源流程

| 信息源 | 一期处理方式 | 说明 |
| --- | --- | --- |
| 邮箱 | 自动同步 | 至少支持一种企业邮箱服务 |
| WhatsApp | 手动导入 + API 结构预留 | 真实 API 视客户条件接入 |
| 企业微信 | 手动导入 + API 结构预留 | 会话同步取决于会话存档权限 |
| 电话 | 手动录入纪要 | 员工必须手动选择对方是谁 |
| 手动记录 | 手动录入/粘贴 | 用于补充线下沟通、会议、备注 |

### 3.3 AI 与人工确认流程

AI 输出不能直接作为正式业务数据，必须进入待确认机制。

处理流程：

1. AI 生成建议。
2. 系统展示建议内容、判断理由、证据来源和置信度。
3. 员工选择接受、修改后接受或拒绝。
4. 员工确认后的内容写入正式业务数据。
5. 系统保留 AI 原始版本和员工确认版本。

## 四、核心功能模块（自研刚需功能）

### 4.1 账号与权限模块

模块定位：提供系统登录、角色管理、团队管理和数据访问控制，是所有业务模块的基础。

核心功能：

- 用户登录、退出。
- 用户管理。
- 角色管理。
- 团队管理。
- 数据范围控制：个人、团队、全公司、指定成员。

验收标准：

- 员工只能查看自己负责的数据。
- 主管可以查看本团队数据。
- 老板可以查看全公司数据。
- 管理员可以配置用户、角色和团队。

### 4.2 合作方信息管理模块

模块定位：统一管理客户、供应商、海外代理、同行、内部对象和未知对象，是系统主数据中心。

核心字段：

| 字段名称 | 字段说明 |
| --- | --- |
| 合作方名称 | 公司、机构、代理或个人主体名称 |
| 合作方类型 | 客户、供应商、海外代理、同行、内部、未知、其他 |
| 官网地址 | 用于官网抓取、背调分析和业务判断 |
| 国家/地区 | 合作方所属国家或主要业务市场 |
| 城市/港口 | 主要城市、港口或服务区域 |
| 业务标签 | 海运、空运、清关、仓储、卡车、快递、铁路等 |
| 来源渠道 | 邮箱、WhatsApp、企业微信、电话、导入、员工录入 |
| 业务负责人 | 绑定负责员工，用于数据权限隔离 |
| 开发阶段 | 当前业务推进阶段 |
| 合作价值评分 | AI 或人工评估的合作潜力 |
| 风险等级 | 低、中、高或未知 |
| 最近联系时间 | 最近一次有效沟通时间 |
| 下次跟进时间 | 下一次计划跟进时间 |
| AI 摘要 | AI 生成的合作方概述 |
| 员工确认摘要 | 员工确认或修改后的正式摘要 |

智能识别规则：

- 通过邮箱域名、官网域名、公司名称、电话区号、WhatsApp 号码、企业微信信息识别合作方。
- 根据官网语言、地址、电话区号、邮箱后缀判断国家/地区、语言和时区。
- 根据沟通内容中的物流关键词识别业务类型。
- 当识别置信度不足时，进入待确认队列。

验收标准：

- 可以新建、编辑、查看合作方。
- 可以给合作方设置负责人、身份标签和开发阶段。
- AI 可建议合作方归属，员工可确认或修改。

### 4.3 客户开发管理模块

模块定位：面向潜在客户和存量客户，管理从线索识别、需求确认、报价、跟进到合作推进的全过程。

核心字段：

| 字段名称 | 字段说明 |
| --- | --- |
| 客户名称 | 客户企业全称 |
| 客户类型 | 品牌商、贸易商、批发商、零售商、电商卖家、采购商等 |
| 客户来源 | 邮箱、WhatsApp、企微、电话、展会、搜索、推荐 |
| 需求线路 | 起运地、目的地、国家、港口、城市 |
| 运输方式 | 海运、空运、快递、铁路、卡车、多式联运 |
| 货物类型 | 普货、敏感货、危险品、冷链、超大件、电商货等 |
| 货量信息 | 件数、重量、体积、柜型、频率 |
| 时效要求 | 期望运输时效和交付时间 |
| 价格敏感度 | 高、中、低或未知 |
| 需求摘要 | AI 总结或员工确认后的客户需求 |

智能识别规则：

- 从沟通内容中识别起运地、目的地、运输方式、货量、时效和报价需求。
- 根据客户反复关注内容识别价格敏感、时效敏感、服务稳定性关注等标签。
- 根据客户回复频率、需求完整度和报价意向判断开发优先级。

验收标准：

- 可以查看客户开发阶段。
- 可以沉淀客户需求和沟通进展。
- AI 可生成客户开发建议。

### 4.4 供应商资源管理模块

模块定位：管理物流供应商、海外代理、仓库、车队、清关行、专线服务商等资源，为客户需求匹配和报价提供基础。

核心字段：

| 字段名称 | 字段说明 |
| --- | --- |
| 供应商名称 | 供应商或代理公司名称 |
| 供应商类型 | 船代、空代、海外仓、卡车公司、清关行、快递代理等 |
| 服务国家/地区 | 供应商覆盖区域 |
| 服务城市/港口 | 优势港口、机场、仓库城市或派送区域 |
| 服务类型 | 海运、空运、清关、仓储、卡派、快递、铁路 |
| 优势线路 | 擅长路线和服务方向 |
| 价格水平 | 低价、中等、高价、未知 |
| 时效稳定性 | 高、中、低或未知 |
| 服务评分 | 人工或 AI 综合评分 |
| 风险记录 | 延误、失联、价格变动、投诉、账期风险 |
| 合作状态 | 待评估、可合作、合作中、暂停、黑名单 |

智能识别规则：

- 根据供应商官网、报价单、邮件签名和沟通内容识别服务范围。
- 根据历史问题记录识别风险点。
- 根据客户需求推荐候选供应商。

验收标准：

- 可以维护供应商基础资料和服务能力。
- 可以记录供应商风险。
- 后续可支持供应商推荐。

### 4.5 联系人管理模块

模块定位：统一管理合作方下的具体人员，沉淀多渠道联系方式、身份角色和人物画像。

核心字段：

| 字段名称 | 字段说明 |
| --- | --- |
| 联系人姓名 | 对方姓名或昵称 |
| 所属合作方 | 关联客户、供应商、代理或内部组织 |
| 联系人身份 | 客户、供应商、代理、内部、未知、其他 |
| 职位/角色 | 采购、老板、销售、操作、财务、客服、代理联系人等 |
| 邮箱 | 邮件沟通地址 |
| 电话 | 手机或座机 |
| WhatsApp 号 | WhatsApp 联系号码 |
| 企业微信 ID | 企业微信外部联系人 ID 或员工 ID |
| 决策影响力 | 决策人、影响人、执行人、未知 |
| 沟通语言 | 英语、中文、西语等 |
| 所在时区 | 用于提醒合适联系时间 |
| AI 人物画像 | AI 根据沟通生成的画像 |
| 员工确认画像 | 员工修改后的正式画像 |

智能识别规则：

- 根据邮箱、电话、WhatsApp、企业微信 ID 自动匹配联系人。
- 根据邮件签名、职位关键词、聊天内容识别职位和角色。
- 当同一联系人出现多个渠道标识时，AI 建议合并。

验收标准：

- 联系人可以关联合作方。
- AI 可以提出联系人身份建议。
- 员工可以确认、修改、新建或合并联系人。

### 4.6 沟通中心模块

模块定位：统一处理邮箱、WhatsApp、企业微信、电话纪要和手动导入内容，是业务信息清洗和归档处理台。

核心功能：

- 邮件列表。
- WhatsApp/企微手动导入。
- 电话纪要录入。
- 待识别消息。
- 待归档消息。
- 手动归档到合作方、联系人和 topic。
- AI 摘要展示。

智能识别规则：

- 自动识别联系人和合作方。
- 自动摘要沟通内容。
- 自动提取物流语义信息。
- 自动判断是否关联已有 topic。
- 低置信度结果进入待确认队列。

验收标准：

- 员工可手动导入聊天记录。
- 员工可录入电话纪要并指定联系人。
- 沟通可归档到合作方、联系人和 topic。

### 4.7 邮箱接入模块

模块定位：完成一期最主要的自动化信息源接入。

核心功能：

- 邮箱账号绑定。
- 收件同步。
- 已发送邮件同步。
- 邮件线程归档。
- 邮件附件保留。
- 邮件进入沟通中心。

验收标准：

- 至少支持一种企业邮箱服务。
- 邮件可同步进入沟通中心。
- 邮件可关联合作方和联系人。

### 4.8 WhatsApp 与企业微信接入框架

模块定位：一期保留多渠道自动化接入能力，同时提供手动导入兜底。

核心功能：

- WhatsApp 账号配置入口。
- WhatsApp 消息数据结构。
- WhatsApp 手动导入。
- 企业微信配置入口。
- 企业微信消息数据结构。
- 企业微信手动导入。
- 同步任务框架。

验收标准：

- 即使真实 API 未开通，员工也能导入 WhatsApp/企微记录。
- 数据结构支持后续 API 消息同步。

### 4.9 Topic 时间线模块

模块定位：将分散沟通整理成可推进的业务主题，是业务推进的核心单元。

核心字段：

| 字段名称 | 字段说明 |
| --- | --- |
| Topic 名称 | 如“美国海运报价机会” |
| Topic 类型 | 业务机会、报价、供应商合作、问题处理、订单推进、内部协作 |
| 关联合作方 | topic 所属合作方 |
| 当前进展 | AI 或员工总结的当前状态 |
| 状态 | 待确认、进行中、已完成、暂缓、无效 |
| 优先级 | 高、中、低 |
| 关联沟通 | 邮件、聊天、电话纪要等证据 |
| 关联任务 | 下一步动作 |
| AI 总结 | AI 生成的 topic 摘要 |
| 员工确认总结 | 员工修改后的正式摘要 |

智能识别规则：

- 新沟通关联已有 topic。
- 无匹配 topic 时建议新建。
- 相似 topic 建议合并。
- 一个 topic 包含多个独立问题时建议拆分。
- 长期未推进时生成提醒。

验收标准：

- 一条沟通可以归入 topic。
- topic 可以展示时间线。
- 员工可以合并、拆分、修改 topic。

### 4.10 AI 秘书模块

模块定位：为员工提供身份识别、沟通摘要、topic 建议、阶段建议、任务建议、人物画像和开发策略建议。

核心功能：

- 身份识别。
- 沟通摘要。
- 合作方归属建议。
- topic 创建/更新建议。
- 阶段推进建议。
- 任务建议。
- 人物画像更新建议。
- 开发话术生成。
- AI 建议队列。

AI 输出要求：

- 输出建议内容。
- 输出判断理由。
- 输出证据来源。
- 输出置信度。
- 不直接覆盖正式数据。

验收标准：

- AI 建议都有待确认状态。
- 员工可以接受、修改接受、拒绝。
- 系统保留 AI 原始输出和员工确认内容。

### 4.11 背调与开发建议模块

模块定位：为客户、供应商和代理生成资料整理、合作价值判断、风险提示和开发建议。

核心功能：

- 发起背调。
- 生成合作方概况。
- 判断潜在物流需求。
- 生成合作价值判断。
- 生成风险提示。
- 生成推荐开发策略。
- 员工编辑报告。

验收标准：

- 背调报告可生成。
- 报告可被员工修改。
- 报告可关联合作方。

### 4.12 任务与阶段推进模块

模块定位：把 AI 建议、员工安排和系统规则转化为明确行动，并记录业务推进状态。

核心功能：

- 任务创建、编辑、完成、忽略、转交。
- 任务关联合作方和 topic。
- 逾期提醒。
- 阶段手动变更。
- AI 阶段建议。
- 阶段历史记录。

阶段建议：

- 新线索。
- 已识别身份。
- 已建立联系。
- 需求确认中。
- 待报价。
- 报价后跟进。
- 试单/样品中。
- 合作谈判中。
- 已合作。
- 暂缓。
- 无效。

验收标准：

- AI 可建议任务和阶段。
- 员工确认后任务或阶段生效。
- 工作台展示待办和逾期。

### 4.13 问题经验库模块

模块定位：沉淀员工在客户开发、供应商合作、报价、清关、时效、账期和客诉中遇到的问题。

核心功能：

- 问题上报。
- 问题分类。
- 处理过程记录。
- 最终结果记录。
- 可复用建议。
- 相似问题检索。

验收标准：

- 员工可新增问题案例。
- 案例可关联合作方和 topic。
- AI 可生成经验总结或处理建议。

### 4.14 个人工作台模块

模块定位：员工每日工作入口，聚合今日待办、逾期任务、AI 建议、待确认事项和重点合作方。

核心功能：

- 今日待办。
- 逾期任务。
- 待确认 AI 建议。
- 重点合作方。
- 活跃 topic。
- 风险提醒。
- 快速录入电话纪要。
- 快速导入聊天记录。

验收标准：

- 员工进入系统后能看到当天要处理的事项。
- 员工能在工作台处理 AI 建议和任务。

### 4.15 团队看板模块

模块定位：面向老板和主管，展示团队开发进度、员工跟进情况、合作机会、逾期风险和 AI 建议处理情况。

核心指标：

- 活跃合作方数。
- 活跃 topic 数。
- 阶段分布。
- 逾期任务数。
- 长期未跟进对象。
- 高价值机会。
- 高风险合作方。
- 员工跟进情况。
- AI 建议未处理数。
- 问题上报数。

验收标准：

- 老板可查看全公司数据。
- 主管可查看团队数据。
- 看板能发现逾期和长期未推进对象。

### 4.16 系统配置模块

模块定位：维护系统运行所需基础配置、字典、渠道账号、AI 参数、权限规则和提醒规则。

核心功能：

- 阶段字典。

验收标准：

## 五、系统角色与权限设计

### 5.1 角色定义

| 角色 | 权限范围 |
| --- | --- |
| 员工 | 查看和处理自己负责的合作方、联系人、沟通、topic、任务 |
| 主管 | 查看本团队数据，处理团队逾期和异常 |

### 5.3 权限控制点

- 合作方查看、创建、编辑、删除。
- 联系人查看、创建、编辑、合并。

- 看板查看范围。
- 系统配置管理。

## 六、安全与合规设计

### 6.1 数据安全

- 用户登录需鉴权。
- 不同角色按数据范围访问。
- 重要操作需要记录日志。
- 邮箱、WhatsApp、企业微信等账号配置需加密存储。
- 附件和沟通内容需按权限读取。

### 6.2 AI 合规

- AI 不直接覆盖正式业务数据。
- AI 输出需保留原始输入、原始输出、员工确认版本。
- AI 背调应标注证据来源。
- AI 对无法判断的信息应输出“无法判断”，不得编造。

### 6.3 渠道合规

- WhatsApp API 接入需确认官方 API 或第三方服务商合规性。
- 企业微信会话同步需确认会话存档权限。
- 邮箱同步需获得账号授权。
- 电话纪要由员工手动录入，不采集录音。

### 6.4 审计日志

建议记录：

- 登录日志。
- 合作方变更日志。
- 联系人合并日志。
- 沟通归档日志。
- AI 建议处理日志。
- 阶段变更日志。
- 任务完成或忽略日志。
- 权限配置变更日志。

## 九、系统上线预期效果

### 9.1 员工侧效果

- 员工减少重复录入和手动整理资料。
- 员工可以统一查看客户、供应商、代理和联系人信息。
- 员工每天能看到待办、逾期和 AI 建议。
- 员工可以基于 AI 背调和开发建议推进客户。
- 员工遇到问题时可以沉淀经验并复用。

### 9.2 管理侧效果

- 老板可以看到团队开发进度。
- 主管可以发现逾期、长期未跟进和高价值机会卡点。
- 管理层不需要逐个员工手动催促。
- 公司可以逐步形成客户、供应商、代理、线路和问题经验的数据资产。

### 9.3 业务侧效果

- 分散沟通可以沉淀为合作方档案和 topic 时间线。
- 客户开发过程更连续。
- 新员工可以通过历史 topic 和问题经验更快进入业务。
- 后续可扩展报价机会、供应商匹配和订单项目推进。

### 9.4 可量化指标

建议上线后观察：

- 沟通记录成功归档比例。
- AI 身份识别建议接受率。
- AI topic 建议接受率。
- 员工每日待办处理率。
- 逾期任务数量变化。
- 老板/主管通过看板发现并处理异常的次数。

## 十、系统价值总结

本系统的核心价值不是单纯记录客户资料，而是把跨境物流业务中分散、隐性的沟通过程转化为可沉淀、可推进、可管理的数据资产。

对员工：

- AI 帮助整理资料、识别联系人、生成摘要、提醒跟进和建议开发策略。
- 员工保留最终判断权，不被系统强制绑定死流程。

对老板：

- 可以看到团队真实开发进度、逾期风险和高价值机会。
- 不需要逐个员工手动催促。

对公司：

- 客户、供应商、代理、线路、报价机会和问题经验逐步沉淀。
- 后续可以扩展为报价管理、供应商资源匹配、订单项目推进和经营分析平台。

一句话总结：

> 跨境物流 AI 协作型 CRM 是员工的业务开发秘书，也是公司沉淀合作过程、管理开发进度和复用业务经验的数据平台。
