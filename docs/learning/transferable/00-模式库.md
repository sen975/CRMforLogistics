## 1. 可靠消息投递 · outbox 模式

【类别】技术模式
【名称】可靠消息投递 · outbox 模式
【一句话】发消息不直接发，先写进待发箱表，后台 worker 轮询再发，防止「发一半丢消息」
【本项目实例】`MessageSendApplicationService` 写 `outbox_jobs` → `MessageOutboxScheduler` 每秒轮询 → `MessageOutboxWorker` 实际发送
【能迁移到】任何「发送不可靠 / 需要重试」的系统：订单通知、消息推送、外部 API 调用

## 2. 多渠道归一化 · 适配器模式

【类别】技术模式
【名称】多渠道归一化 · 适配器模式
【一句话】不管消息从哪个渠道来，先转成统一的内部标准再落库——渠道差异被隔离在外层
【本项目实例】Email / WeCom / ChatApp / WhatsApp 各自 channel 层 → 归一化成标准 message → 统一会话展示
【能迁移到】任何「多个外部系统 → 一个统一域模型」的系统：支付聚合、IM 聚合、设备接入
