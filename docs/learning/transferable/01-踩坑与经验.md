## 1. 异步任务的日志/追踪不贯穿

【类别】踩坑经验
【名称】traceId/MDC 不自动传到异步线程
【一句话】后台 scheduler/worker 的日志不会带请求的 traceId，排查异步任务只能靠日志密度 + 时间戳，加全局 traceId 过滤器对它们无效
【本项目实例】`MessageOutboxScheduler`、`WeComChatDataSyncRuntime` 等异步链路
【能迁移到】任何用异步/多线程 + 日志排查的系统

## 2. 核心域直接依赖渠道网关 = 越界

【类别】踩坑经验
【名称】核心模块不该 import 具体渠道实现
【一句话】依赖方向应该是「业务 → 基础设施、业务 → 渠道」，反过来就会让改渠道波及核心
【本项目实例】`MessageOutboxWorker` → `ChatAppOutboundGateway`（架构债清单里的第 1 处）
【能迁移到】设计分层时先定好依赖方向；review 时盯反向 import
