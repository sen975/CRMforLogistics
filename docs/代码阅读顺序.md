# 代码阅读顺序（从零开始）

> **用途**：从零开始读本项目代码的推荐顺序。按「依赖方向 + 业务分层」排列——越靠前的越要先看，因为后面的都建立在它之上。
> **来源**：基于 2026-08-22 会话产出的「全量审计阅读顺序」，**2026-08-26 按当前代码重新核验**（主类、迁移、mapper/entity 数、渠道文件清单已更新）。
> **基准**：`codex/message-center-presplit-runtime`，后端源码根 `demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter`（311 Java 文件），前端 `demo/message-center-spring/frontend`。

每个阶段给「读什么 + 审什么」。上手建议放文末。

---

## 阶段 0：启动、全局配置、演进时间线（先知道系统长什么样）

- 入口 [InstallationImportApplication.java](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/InstallationImportApplication.java)（**注意：主类名就是这个**，不是 MessageCenterApplication；同目录还有 App.java、AppCommand.java）
- [pom.xml](demo/message-center-spring/backend/pom.xml) — 依赖和版本（Spring Boot 3.4.5、MyBatis-Plus、PostgreSQL、MinIO、无 Redis）
- `application.yml` + `application-dev.yml` + [deploy/message-center.env.example](deploy/message-center.env.example) — 看有哪些开关（`WECOM_ENABLED` 等）
- [config/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/config/) 里的 `AppConfig.java`（配置聚合核心）
- **Flyway 迁移 V1→V25**（[db/migration/](demo/message-center-spring/backend/src/main/resources/db/migration/)）——最省力的「项目演进时间线」，每个迁移对应一个功能阶段（V1 身份/联系人 → V2 渠道/会话/消息 → V12 企微会话存档 → V15 广播 → V23 会话身份 → V25 日报来源会话）

**审查焦点**：配置有没有硬编码密钥、开关是否安全默认值、迁移是否幂等且不回删数据。

## 阶段 1：核心领域模型（业务地基，全项目最重要的词汇表）

按依赖顺序读 [entity/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/entity/)（27 个实体）：

1. `UserEntity` → `RoleEntity` → `CompanyEntity`
2. `ChannelAccountEntity` → `ContactEntity` → `ContactIdentityEntity`（渠道账号/联系人/身份，核心）
3. `ConversationEntity` → `MessageEntity` → `SessionEntity`
4. 附属：`AttachmentEntity`、`AuditLogEntity`、`MessageStatusEventEntity`、`OutboxJobEntity`、`ChannelEventEntity`
5. 渠道专属：`WeCom*` 6 个（SourceConversation/Party/ChatDataIngestFailure…）、`ChatAppBroadcast*` 5 个、`CallRecord*` 2 个、`Template*` 3 个

**审查焦点**：唯一键、外键关系、`counts_as_unread`/`direction` 这类语义字段、`contact_identity_id` 是否被错误地强制非空。

## 阶段 2：基础设施与横切关注点

- [infrastructure/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/infrastructure/)：`CredentialCipher`（密钥加密，最敏感）、`MinioStorage`、`SecurityUtil`、`ContactPointUtil`
- [typehandler/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/typehandler/)：Jsonb/UUID 类型处理器
- config 剩余：`SecurityConfig`、`TokenAuthenticationFilter`、`PasswordConfig`、`CredentialConfig`、`CorsConfig`、`MyBatisPlusConfig`、`MinioConfig`、`FunAsrConfig`、`CallRecordConfig`

**审查焦点**：密钥加密算法和 master key 来源、JWT 校验、CORS、密码哈希。

## 阶段 3：持久层 mapper/

跟着实体走，共 **39 个**（38 个 Mapper 接口 + `WeComCredentialRow`）。不用全细看，重点审有复杂 SQL 的：`ConversationMapper`、`MessageMapper`（联表/排序/未读统计/游标分页）、`OutboxJobMapper`（SKIP LOCKED）。

## 阶段 4：认证与权限

- [service/auth/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/service/auth/)：`BootstrapService`、`AuthSessionService`、`UserDetailsServiceImpl`
- `web/AuthController` + `SecurityConfig` + `TokenAuthenticationFilter`

**审查焦点**：会话如何建立、token 如何校验、是否有越权路径。

## 阶段 5：核心 CRM 业务（联系人/会话/消息主链路）

- [service/contact/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/service/contact/)：`ContactService`、`ContactGroupService`
- [service/conversation/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/service/conversation/)：`ConversationAccessService`、`UnifiedConversationService`
- [service/message/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/service/message/)：`MessageQueryService`、`ThreadService`、`MessageSendApplicationService`、`MessageOutboxScheduler/Worker`、`TemplateMessageTextResolver`
- `service/channel/`：`ChannelAccountService`
- 对应 web：`ContactController`、`ThreadController`、`MessageController`、`ConversationController`、`ChannelSettingsController`

**审查焦点**：一条消息从「发」到「落库」到「被查出来」的完整链路；发送走 outbox（`MessageSendApplicationService` 写 `outbox_jobs` → 1s 轮询）；权限过滤是否在服务端做。

## 阶段 6：各渠道逐个过（从简到繁）

1. **Email**（最简单，13 文件）：[channel/email/](demo/message-center-spring/backend/src/main/java/com/crmforlogistics/messagecenter/channel/email/)（`EmailSendService`、`EmailSyncService`、`OpenSslImapClient`、`EmailAttachmentStore`）——IMAP/SMTP 同步，先建立「渠道 → 规范化 → 落库」心智模型
2. **ChatApp**（40 文件）：`channel/chatapp/` + `service/chatapp/`（webhook 接收、模板、`broadcast` 子包、`ChatAppPollingProjector`）
3. **WhatsApp 模板**（15 文件）：`service/whatsapp/template/`（`WhatsAppTemplate*`、媒体上传、对账）
4. **通话记录**（8 文件）：`service/callrecord/`（`CallRecordService`、`CallRecordStateMachine`、`FunAsrClient` 转写、`MinioAudioStore`）——一条独立的旁路
5. **WeCom**（最大、最敏感，76 文件）：`channel/wecom/` + `service/wecom/`，用子顺序：**凭证授权主线**（`WeComAuthorizationService`）→ **数据合同**（`WeComChatDataSyncRuntime`/`WeComChatDataStore`/`WeComChatDataNormalizer`）→ **资料同步**（`WeComPartyProfileService`）→ **投影**（`WeComMessageProjector`）→ **viewer**（`WeComViewerService`）→ **回补/留存/审计**

**审查焦点**：每个渠道是否都走「上游 → 规范化 → 落库 → 投影」而不是各自为政；错误/失败是否有持久化记录不静默丢。

## 阶段 7：事件与异步

- `service/event/EventHub`、`service/message` 的 Outbox、各 Scheduler（`MessageOutboxScheduler` 1s、`ChatAppSyncScheduler` 5s+5min、`EmailSyncScheduler` 5min、`WeComChatDataSyncRuntime` 60s、`WhatsAppTemplateReconciliationScheduler` 300s）、`web/SseController`

**审查焦点**：异步任务是否有重试上限、幂等、不会丢事件。
