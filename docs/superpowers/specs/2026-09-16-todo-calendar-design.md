# 待办日历与企业微信提醒设计

## 目标

在现有消息中心中增加一个可持续使用的“待办日历”工作台：用户通过月历选择日期，查看并手动维护当天待办；在当天可触发一次企业微信应用消息提醒。前端只调用本项目后端，后端通过现有企业微信安装凭据和官方消息发送接口完成推送。

## 范围与非目标

- 范围：独立 `/todo-calendar` 路由、月历日期选择、待办新增/完成/删除、当天待办汇总、官方 API 提醒发送、服务端按用户持久化、响应式布局。
- 非目标：多人协作、重复任务、提醒定时调度、待办服务端同步。

## 体验与视觉

页面采用“纸张工作台”语言，贴合物流运营人员手动记事的场景：

- 背景为暖灰纸色，主体为略带阴影的米白纸张；墨黑文字配橙红批注色，绿色仅用于完成状态。
- 标题使用衬线显示字体，正文使用系统无衬线字体；按钮、时间和状态采用紧凑的工具标签。
- 月历格以细线和局部虚线分隔，选中日期使用橙红色手绘圈标记；待办卡片使用纸片叠放与短横线，不使用大圆角卡片。
- 页面保留键盘焦点、移动端堆叠布局和 `prefers-reduced-motion` 降级。

## 页面结构

```
┌─────────────────────────────────────────────────────────┐
│ 待办日历       2026年9月        ← →   今天   新建待办   │
│ 一页纸安排今天的运输、客户和跟进                         │
├───────────────────────┬─────────────────────────────────┤
│ 月历（点击日期）       │ 9月16日 · 星期三                 │
│  日 一 二 三 四 五 六   │ 今日 3 项 · 已完成 1             │
│  …                     │ [ ] 确认青岛仓出库时间   09:30   │
│                       │ [✓] 回访客户李宁           13:00   │
│                       │ [ ] 发送装车照片             17:00   │
│                       │                                 │
│                       │ 企业微信提醒                   │
│                       │ [发送今日提醒]  官方 API · 最近…    │
└───────────────────────┴─────────────────────────────────┘
```

月历显示任务数量小圆点；点击日期只改变共享的 `selectedDate`，右侧详情从任务 owner 读取该日期任务。新增待办表单要求标题，时间和备注可选；保存后立即回到详情列表。完成/删除均为即时本地操作。

## 数据与 owner

`TodoCalendarPage` 只负责展示和事件编排；待办模型与存取逻辑放在同页面旁的 `todoStore.ts`，作为本地数据 owner：

```ts
type TodoItem = {
  id: string;
  date: string;       // YYYY-MM-DD，本地时区
  title: string;
  time?: string;      // HH:mm
  note?: string;
  completed: boolean;
  createdAt: string;
};
```

待办由后端 `todo_items` 表按 `user_id` 隔离保存，前端通过 `/api/todos` CRUD；旧版浏览器缓存仅在首次加载且服务端为空时迁移一次。发送记录只保存最近 10 条，包含日期、时间、任务数和后端返回的 `messageId`；前端调用 `sendTodoReminder`，后端 `/api/wecom/send-todo-reminder` 根据当前登录账号绑定的企业微信身份发送，不在 UI 中传递密钥。

## 验收与测试

- 单元测试覆盖日期筛选、任务新增/切换完成/删除、本地存储损坏降级、提醒记录上限。
- 页面测试覆盖点击日期切换详情、打开新增表单并保存、勾选完成、发送提醒后出现结果文案。
- 运行 `npm run build` 和前端测试脚本；检查桌面与窄屏布局，确认现有路由和导航行为不回归。
