# 联系人备注展示与标签恢复设计

## 目标

恢复 Spring 消息中心迁移时丢失的 CRM 联系人标签能力，并让人工备注在所有联系人展示位置覆盖原始昵称。原始 `contacts.display_name` 保持不变，备注只影响展示名称。

## 边界

- 本设计处理 CRM 联系人备注与 `contact_tags` / `contact_taggings`。
- 企业微信通讯录标签属于外部平台管理能力，继续保持独立，不写入 CRM 联系人标签。
- 不修改联系人身份、会话归属、企业微信消息或 Topic 生成语义。

## 展示名称合同

前端定义唯一联系人展示名规则：

1. 非空人工备注 `remark`。
2. 非空原始昵称 `displayName`。
3. 兜底文案“未命名”。

左侧联系人列表、联系人会话标题、联系人详情标题和发送页联系人选项统一消费该规则。保存备注后同时失效联系人详情、联系人列表和统一会话列表缓存，使新名称立即可见。

## 标签合同

`ContactService` 是联系人投影的 owner。联系人列表和详情响应在现有字段基础上增加：

```text
tags: [{ id, name, color }]
```

标签按名称和 ID 稳定排序，只返回 `status = 'active'` 的标签。查询由专用 mapper 完成，不在 controller 或前端拼接数据库语义。

联系人标签更新采用替换语义：服务端在一个事务内规范化输入、复用同名活动标签、创建不存在的标签，并将联系人的标签关系替换为请求集合。空集合表示清空标签；重复项按不区分大小写去重；空名称忽略；名称长度沿用数据库上限 100 字符。

更新端点：

```text
PUT /api/contacts/{id}/tags
{ "tags": [{ "name": "重点跟进", "color": "blue" }] }
```

服务端在写入前复用现有联系人访问控制，禁止通过标签端点修改不可访问联系人。

## 前端交互

联系人详情保留现有备注编辑区，并新增“标签”行：

- 查看态使用 Ant Design `Tag` 展示标签，没有标签时显示 `-`。
- 编辑态使用可创建多选输入，允许选择已有标签或输入新标签。
- 保存成功后刷新联系人详情、联系人列表和统一会话列表。
- 保存失败时保留草稿并显示后端错误，不伪造成功状态。

本轮不新增独立标签管理页面；标签创建通过联系人标签编辑按需完成。

## 验收

- 备注与原始昵称同时存在时，列表、会话标题、详情标题和发送页只显示备注。
- 清空备注后恢复显示原始昵称。
- 联系人响应返回其活动标签；禁用标签不返回。
- 标签替换、清空、去重和同名复用均有后端测试。
- 联系人详情可展示、添加、删除并保存标签，失败时保留编辑内容。
- 前端专项测试、前端构建以及后端联系人专项测试通过。
