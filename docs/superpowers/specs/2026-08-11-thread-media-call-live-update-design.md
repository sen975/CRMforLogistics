# 会话图片与电话记录实时展示设计

**日期：** 2026-08-11
**状态：** 已确认
**适用范围：** Spring 消息线程、ChatApp 本地附件、电话记录时间线

## 问题

- 电话记录由 `ThreadPage` 单独渲染，未按 `direction` 设置左右布局，导致 `outbound` 仍在左侧。
- ChatApp 上传服务已把媒体保存为 `attachments`，但 `MessageResponse` 不包含附件投影，前端只能显示图片图标。
- 会话中的电话记录只在初次加载、手动刷新或普通消息 SSE 到达时更新；上传成功回调未接线，转录状态也没有活动期轮询。

## 唯一主线

1. `attachments` 表是本地媒体真源。线程和消息详情响应返回结构化、只读附件元数据：附件 ID、媒体类型、MIME、文件名和大小，不返回 MinIO object key。
2. `/api/media/{attachmentId}` 在服务端执行会话权限校验，按附件 ID 解析 MinIO object key，并返回真实 Content-Type。浏览器继续通过带 Bearer 鉴权的 API 下载 blob。
3. 图片气泡显示真实缩略图并支持点击预览；加载中保留稳定尺寸，下载失败才降级为图标与文件名。
4. 电话记录使用与普通消息相同的方向语义：`outbound` 右侧绿色，`inbound` 左侧灰色。
5. 电话上传成功后立即重新读取联系人时间线。存在 `queued` 或 `processing` 时每 2 秒更新；进入 `completed` 或 `failed` 后停止轮询。

## Cams 边界

demo 的 Cams 媒体流程只作为后端适配参考：由后端用 `GeneratePresignedUrl` 或服务端 OSS 签名获取短时资源，缓存后写入本地附件，再通过同一 `/api/media/{attachmentId}` 合同提供。前端不得接收或持久化 Cams/OSS 临时 URL。本轮先闭合已由 Spring 上传并落入 MinIO 的图片；Cams 历史媒体预缓存不在本轮伪装实现。

## 错误与资源边界

- 未找到附件或当前用户无权访问时统一返回 404，不泄露对象存储信息。
- 图片 blob URL 在组件卸载或附件变化时释放。
- 电话轮询只在当前联系人存在活动转录时运行，间隔固定 2 秒，不永久常驻。
- 不修改 ChatApp 模板同步、账号配置、联系人身份或通话转录状态机。

## 验收

- 呼出电话在右侧，呼入电话在左侧。
- 当前已提交的 ChatApp 图片消息显示真实图片而不是仅显示图标。
- 上传电话成功后无需刷新即可出现；排队、转录和完成/失败状态自动更新。
- 后端附件投影和授权媒体读取测试通过。
- 前端方向、活动轮询、真实图片及失败降级测试通过。
- 浏览器中完成一次真实图片渲染和电话上传/状态变化检查。
