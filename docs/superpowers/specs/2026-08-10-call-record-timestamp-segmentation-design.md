# 通话转录真实时间戳与可读性分段设计

## 目标

为通话转录结果提供真实时间轴和更易读的文本展示：使用 FunASR 返回的真实 VAD/句级边界作为时间戳，并在每个真实语音区间内按中英文标点换行。转录原文内容不改写，历史录音通过现有重新转录入口重新生成时间轴。

## 非目标

- 不根据音频总时长、文字长度、字符数或固定间隔推算时间戳。
- 不在 Spring 或前端私造新的时间真相。
- 不切换 SenseVoice，不增加额外常驻 ASR/VAD 模型，也不引入新的 CPU 常驻负载。
- 不修改与通话记录无关的 ChatApp、WeCom、登录或联系人链路。

## 方案选择

采用 SenseVoice 已加载的 FSMN-VAD 真实边界。这条路线复用当前模型和 CPU 预算，同时兼顾中文为主、偶尔英文的录音。

未采用切换 Paraformer。Paraformer 的中文时间戳能力更强，但会改变现有模型合同、语言表现和资源占用，超出本轮“只改善可读性”的范围。未采用文字长度/总时长估算，因为它无法表示真实发言位置，生成的时间戳会误导播放定位。

## 架构与数据流

FunASR 服务把模型的 `sentence_info` 真实毫秒边界映射为 OpenAI `verbose_json.segments`，Spring adapter 是该外部响应的唯一解析 owner。Spring 继续请求 `verbose_json`，只消费响应中的结构化 `segments`，不在其他层重复解析或生成时间。只有同时具备有限的 `start`、`end`、非空文本且满足音频时长边界的区间才进入领域 `TranscriptSegment`。

当上游只返回文本或没有可验证的真实边界时，adapter 保留完整原文并返回空 segments。Spring 状态机继续保存空列表，前端展示原文而隐藏时间轴。禁止使用 FunASR 服务端按文字长度平均分配时长的 fallback 作为真实时间戳来源。

前端 `CallRecordDetail` 继续消费 API 返回的 `TranscriptSegment[]`。每个 segment 显示一个 `startSeconds-endSeconds` 时间范围；segment 文本只做显示层换行，标点规则覆盖中文 `。！？；` 和英文 `.?!;`，不改变字符、顺序或内容，也不拆成新的时间区间。

## 历史录音

历史记录若 `segments` 为空，不能从数据库中已有的纯文本恢复真实时间。现有 retry 合同将扩展为允许 `failed`，以及“已完成但 segments 为空”的记录重新入队；其他状态继续返回冲突，防止重复排队。详情页只在这两种可重转录状态显示既有“重新转录”操作，不增加新的页面结构。

worker 读取原音频并重新调用 FunASR；成功后以新响应中的机器原文和真实区间覆盖机器转录结果，但保留人工修订列表和 `currentRevisionId`。失败仍按现有状态机重试/失败规则处理；重新转录期间保留旧机器结果，不清空已有原文，API 仍按状态合同决定是否展示结果。

## 错误处理与边界

- 缺少 `text` 或响应结构非法：返回 `FUNASR_INVALID_RESPONSE`。
- segments 字段缺失或不是数组：返回 `FUNASR_INVALID_RESPONSE`；合法空数组表示转录完成但没有时间轴。
- 非法区间（负数、`end < start`、超出可信音频时长、时间倒退）：拒绝整份响应，避免保存错误时间轴。
- 真实区间数量、文本长度和总文本长度继续沿用现有上界，防止无界响应。

## 验收

- Spring adapter 单元测试覆盖 `segments` 映射、空/非法时间戳和禁止估算；真实录音验收确认 FunASR 将 `sentence_info` 的毫秒边界正确映射为响应 `segments`。
- 状态机/worker 回归测试确认空 segments 仍可完成，非空真实区间正确持久化。
- retry 测试覆盖失败记录、已完成但无时间轴记录、已有时间轴和排队中记录，并确认人工修订不被删除。
- 前端测试确认中文与英文标点仅触发显示换行，不改变文本和时间区间。
- 重新转录一条历史录音，数据库中的结果包含真实区间；无区间响应只显示原文，不显示伪时间轴。
