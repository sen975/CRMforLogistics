# ChatApp 模板库自动同步设计

**状态：** 用户已确认设计，实施计划已制定，待实施

**日期：** 2026-07-30

## 1. 背景与范围

消息中心当前已经具备通过阿里云 ChatApp API 拉取模板列表和模板详情的能力，但 `/api/templates` 只读取本地 JSON 快照。模板同步主要依靠手动执行 `sync-templates`，消息同步是否先拉模板还由 `SYNC_TEMPLATES_BEFORE_MESSAGES` 控制。

本设计把模板库同步改为消息中心 web 运行时的后台能力：启动后异步拉取一次，之后每 5 分钟全量对账；有成功变化时通过现有 SSE 通道通知页面重新读取模板。目标是上游正常时在 5～10 分钟内反映模板新增、修改和删除。

本轮不接入 `ChatAppAudit` 作为关键同步路径。阿里云的审核回调只携带审核状态等事件信息，不携带完整模板正文，也不覆盖所有模板增删改；后续如有秒级更新要求，可将其作为“立即触发一次全量拉取”的信号，但定时对账仍保留。

## 2. 目标与非目标

### 目标

- 后端成为模板同步的唯一 owner，页面只消费本地成功快照。
- 上游完整结果覆盖本地快照，包含删除的模板语言记录。
- 单轮失败不污染上一版可用快照。
- 变更只在实际发生时通知页面，且不触发消息列表刷新。
- 启动、定时和显式单次同步遵守有界并发、文件锁和可关闭生命周期。

### 非目标

- 本轮不把模板正文放入 SSE 事件。
- 本轮不把 ChatApp 审核回调当作模板库真源或完整变更通知。
- 本轮不重做消息中心的 PostgreSQL、MinIO 或消息同步架构。
- 本轮不删除现有 `sync-templates` CLI；它继续提供一次性同步入口。

## 3. 方案选择

### 推荐：启动拉取 + 5 分钟全量对账 + SSE 失效通知

每轮完整读取模板列表并读取每条模板的详情，在内存中构造新快照。整轮成功后原子替换本地文件；快照业务内容有变化时发送 `templates-changed` SSE 事件。页面收到事件后重新请求 `/api/templates`。

该方案直接复用已有 API、`TemplateStore` 和 SSE 基础设施，能够发现上游删除，且不把外部回调的可靠性引入关键链路。

### 未选方案：仅依赖 ChatAppAudit 回调

回调不是完整模板变更流，缺少正文并且需要额外配置控制台回调地址，不能独立保证模板库一致性。

### 未选方案：每次消息同步顺带刷新模板

模板更新时效受消息同步触发影响，且模板 API 延迟会拖慢消息同步；两类任务的失败边界也会相互污染。

## 4. 组件与 owner 边界

### `ChatAppTemplateGateway`

封装阿里云 SDK 的 `ListChatappTemplate` 和 `GetChatappTemplateDetail` 调用。只负责请求映射、响应校验、超时和上游错误，不负责本地文件或页面事件。

### `ChatAppTemplateSynchronizer`

模板同步的核心 owner。负责分页、详情获取、数量上限、快照组装、业务内容比较、跨进程锁和原子提交，并返回结构化同步结果。禁止由 HTTP route、页面脚本或 `ChatAppHistorySyncService.syncMessages()` 私自维护另一套模板真相。

### `TemplateStore`

负责读取成功快照和原子写入快照。写入使用同目录临时文件并替换目标文件；替换失败时旧文件保持可读。模板记录的稳定键为 `templateCode|languageCode`（大小写和两端空白归一化）。

### `ChatAppTemplateSyncRuntime`

负责 web 进程内的启动触发、5 分钟调度、任务关闭和结构化日志。它不拥有模板业务规则，只调用同步器并在成功变化时通知 `EventHub`。

### `EventHub` 与页面

`EventHub` 负责发布有类型的 SSE 事件。页面只把 `templates-changed` 当作缓存失效信号，重新请求 `/api/templates`，不在前端推断模板内容或同步状态。

## 5. 数据流与一致性

1. web 服务开始监听后，runtime 异步触发第一轮同步。
2. 同步器取得模板锁，分页读取列表；每条记录再读取详情。
3. 同步器在内存中构造完全由本轮上游结果组成的新记录集合，不把旧集合合并进来。
4. 列表页或详情请求、响应校验、数量上限、超时任一失败，整轮失败并保留旧快照。
5. 整轮成功后，按稳定键排序，计算忽略本地 `updatedAt` 的业务内容摘要。
6. 摘要发生变化时，`TemplateStore` 原子替换文件并向 `EventHub` 发布 `templates-changed`；摘要未变化时不写文件、不发事件。
7. `/api/templates` 始终读取最近一次成功快照。页面收到事件后重新拉取并更新模板选择器。

模板详情中的 `raw` 等上游字段参与业务内容比较，因此审核状态或组件内容变化也能触发更新；本地生成的时间戳不参与比较。

## 6. 配置与资源边界

新增配置合同：

| 配置 | 默认值 | 约束 |
| --- | ---: | --- |
| `CHATAPP_TEMPLATE_AUTO_SYNC_ENABLED` | `true` | 严格布尔值 |
| `CHATAPP_TEMPLATE_SYNC_INTERVAL_SECONDS` | `300` | `300～600` |
| 单请求超时 | `15` 秒 | 实现内固定上界 |
| 单轮超时 | `240` 秒 | 实现内固定上界 |
| `TEMPLATE_PAGE_SIZE` | `50` | `1～50` |
| `TEMPLATE_MAX_PAGES` | `40` | `1～40` |
| 单轮模板语言记录数 | `2,000` | 超出即整轮失败 |

单轮最大结果是 40 页、每页 50 条，即最多 2,000 条模板语言记录。达到页数上限仍返回满页，或上游总数超过 2,000 时，不能把截断结果保存为完整快照。

自动同步只在 `web` 命令启动。缺少 `CUST_SPACE_ID` 时不创建自动同步任务，只记录一次配置缺失日志，消息中心仍可启动并提供旧快照。阿里云凭据沿用当前显式密钥和默认凭据链逻辑，不在日志中输出密钥。

runtime 使用单线程守护调度器，保证进程内单飞；同步文件旁的锁文件保证 CLI 或其他进程不能同时提交同一快照。关闭时先停止调度器并取消在途任务，再关闭 SSE 和 HTTP 服务。

## 7. 失败处理与观测

- 任一上游请求失败、返回空体、业务码失败、详情缺失、超时或达到上限：本轮失败，旧文件不变。
- 本轮失败不在同一轮内密集重试，由下一次调度重新尝试。
- 锁被占用时本轮跳过并记录 `template_sync_lock_busy`，不等待、不覆盖。
- 记录结构化事件：`started`、`succeeded`、`unchanged`、`failed`、`skipped_not_configured`、`lock_busy`，包含耗时、抓取数、保存数和失败阶段；禁止写入凭据、模板正文或完整响应中的敏感字段。
- 启动同步失败不影响 HTTP 服务启动；页面继续使用旧快照并可在下一轮自动恢复。

## 8. SSE 合同

模板发生成功变化时发布：

```text
event: templates-changed
data: {"count":2}
```

事件只表达“模板资源已失效”，不携带模板正文。页面为该事件注册独立处理器，仅重新请求 `/api/templates` 和重绘模板控件；现有消息事件仍沿用“刷新消息并提示有新消息”的行为。SSE 断线不影响后台同步，页面重新连接或手动刷新后仍会读取最新快照。

## 9. 测试与验收

### 同步器单元测试

- 新增、修改、删除分别进入新快照。
- 任一列表页或详情失败时旧快照保持不变。
- 超过 40 页或 2,000 条时不提交截断数据。
- 无变化不写文件、不发事件；有变化只发一次事件。
- 并发触发只执行一轮；锁被其他进程持有时安全跳过。
- 原子替换失败时旧文件仍可读取。

### 配置与运行时测试

- 同步间隔越界被拒绝。
- 自动同步关闭、缺少 `CUST_SPACE_ID` 时 web 服务仍能启动且不创建任务。
- 关闭 runtime 后不再触发同步、不再写快照。

### HTTP/SSE 集成测试

- `/api/templates` 返回最近一次成功快照。
- 只收到 `templates-changed` 时页面重新拉取模板，不刷新消息列表或弹出消息提示。

### 验收命令与标准

```text
mvn -q -f demo/message-center-demo/pom.xml test
```

另外运行使用模拟 ChatApp 模板网关的集成场景，覆盖新增、修改、删除、失败回滚、上限拒绝和 SSE 通知。上游正常时，模板变更应在 5～10 分钟内进入消息中心；上游异常时，页面继续使用上一版完整模板库。
