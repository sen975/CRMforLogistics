# 账户生命周期与用户资料设计

## 目标

补齐普通用户从注册到日常资料维护的完整账户生命周期，并把角色管理、密码重置和头像来源收敛到服务端统一合同。

本设计支持：

- 用户使用自定义登录 ID 注册；注册成功后自动登录。
- 新用户默认且仅拥有最低权限角色 `agent`。
- 用户登录后修改昵称、上传头像，并凭原密码修改密码。
- 管理员查看用户、调整角色并为忘记密码的用户重置密码。
- 已绑定企业微信的账号优先显示企业微信头像；不可用时回退到用户上传头像，再回退到昵称首字占位头像。代开发应用的敏感头像不依赖企业微信 Web 登录或 `user/get`，必须由绑定成员完成独立 OAuth2 授权后才会入库。

## 边界

- “自定义用户 ID”指不可修改的登录用户名；数据库主键继续使用系统生成的 UUID，不允许用户指定数据库 UUID。
- 不引入邮箱、手机验证码、恢复码、找回链接或未登录自助重置密码。
- 不允许只凭用户名修改密码；普通用户必须验证原密码，忘记密码由管理员重置。
- 不改变现有企业微信消息、联系人、Topic、摘要或会话展示合同。
- 不在前端推断角色、企业微信绑定身份或头像优先级。

## 架构与所有权

新增账户应用服务作为用户资料、密码、头像优先级和管理员账户操作的唯一 owner。`AuthController` 仅负责公开注册、登录和退出；账户 controller 负责当前用户操作；管理员 controller 只做 HTTP 映射和 `ADMIN` 权限接线。

数据库继续以 `users`、`roles`、`user_roles` 和 `user_sessions` 为身份真源。用户上传头像保存在现有 MinIO，`users` 只保存当前对象键及受控元数据。企业微信头像从当前绑定对应的已入库员工资料读取，不在账户查询时调用企业微信上游。头像资料的写入由独立授权服务负责：账号面板创建一次性、五分钟有效的 `snsapi_privateinfo` OAuth2 授权；回调仅在授权成员、企业、安装版本和当前绑定均一致且企业微信返回 `user_ticket` 时取得成员详情并保存头像。Web 登录组件不请求敏感资料字段，常规 `user/get` 同步返回头像为空只记录资料不完整状态，不覆盖既有头像。

前端 `useAuth` 消费账户资料合同，登录用户名不再同时承担展示昵称职责。账户抽屉和顶栏使用同一份当前账户投影。

## 注册与校验

公开接口 `POST /api/auth/register` 接收：

```json
{
  "username": "agent_01",
  "displayName": "张三",
  "password": "Example123"
}
```

规则如下：

- `username` 先执行 NFKC 归一化并去除首尾空白，归一化后的长度为 3–32，只允许 ASCII 字母、数字、点、下划线和连字符，且首字符必须是字母或数字。
- 归一化用户名再转为小写生成 `username_normalized`；唯一性以该字段为准，`username` 保存归一化但保留大小写的值。
- `displayName` 可省略；提供时去除首尾空白后长度为 1–50，省略时使用用户名。
- `password` 长度为 8–72，至少包含一个字母和一个数字，不写入日志或错误详情。
- 用户创建与 `agent` 角色分配在同一事务中完成；用户名并发冲突返回 `409 USERNAME_ALREADY_EXISTS`。
- 注册成功立即签发与普通登录相同的会话 token，并返回用户名和角色。

## 当前账户合同

`GET /api/account/profile` 返回：

```json
{
  "id": "uuid",
  "username": "agent_01",
  "displayName": "张三",
  "roles": ["AGENT"],
  "avatar": {
    "source": "WECOM",
    "contentUrl": "https://example.invalid/avatar",
    "initial": "张",
    "revision": "stable-revision"
  }
}
```

`avatar.source` 只能是 `WECOM`、`UPLOAD` 或 `INITIAL`：

1. 账号存在有效企业微信绑定，且对应已入库员工资料的 `avatar_url` 非空时返回 `WECOM`。
2. 否则，用户存在已上传头像对象时返回 `UPLOAD`。
3. 否则返回 `INITIAL`，`initial` 取昵称去除空白后的首个字符；昵称不可用时取用户名首字符。

`WECOM` 的 `contentUrl` 是已入库的企业微信头像 URL；`UPLOAD` 的 `contentUrl` 固定为 `/api/account/avatar/content`；`INITIAL` 的 `contentUrl` 为 `null`。`revision` 在企业微信或上传头像生效时提供稳定的缓存版本，`INITIAL` 时为 `null`。

账户面板在企业微信已绑定但 `avatar.source` 不是 `WECOM` 时显示“授权企业微信头像”。普通浏览器以二维码呈现授权 URL，企业微信内打开时直接跳转授权 URL；页面每两秒查询一次授权终态，只有 `SUCCEEDED` 才刷新账户资料。失败、过期或关闭弹窗会停止轮询，失败原因只显示结构化错误码，不显示 OAuth code、state、ticket 或访问令牌。

上传头像内容通过需要认证的 `GET /api/account/avatar/content` 读取。前端使用 API 客户端携带 Bearer token 获取 Blob，再创建浏览器对象 URL；不把 token 放入图片 URL。企业微信头像使用已存的上游 URL，加载失败时前端只降级到 `initial`，不改变服务端资料真相。

`PATCH /api/account/profile` 只允许修改 `displayName`。用户名和角色不在该接口中修改。

## 头像上传

`POST /api/account/avatar` 使用 `multipart/form-data` 上传单个文件，支持 JPEG 和 PNG，文件最大 2 MiB，图像宽高均不得超过 4096 像素。后端同时校验声明 MIME、文件签名和实际可解码尺寸，拒绝伪造扩展名或无法解码的内容。

对象键格式为 `user-avatars/{userId}/{uuid}`，不使用原始文件名。替换时先写入新对象，再原子更新数据库指针；数据库更新失败时删除新对象，更新成功后删除旧对象。旧对象删除失败只记录结构化告警，不回滚已经生效的新头像。

`DELETE /api/account/avatar` 删除用户上传头像。若企业微信头像当前生效，删除操作只删除备用上传头像，不影响企业微信头像。

数据库迁移为 `users` 增加：

- `avatar_object_key`
- `avatar_mime_type`
- `avatar_size_bytes`
- `avatar_updated_at`

## 密码管理

`PUT /api/account/password` 接收原密码、新密码和确认密码。原密码必须通过当前用户的密码散列验证，新密码使用与注册相同的强度规则，且不得与原密码相同。

修改成功后撤销该用户全部旧会话并签发一个替代 token 返回给当前客户端，使当前操作继续有效，其他设备必须重新登录。

企业微信自动创建的账号拥有系统生成的未知随机密码，因此不能绕过原密码自行建立密码；需要密码登录时由管理员先执行重置。

## 管理员用户管理

新增仅 `ROLE_ADMIN` 可访问的用户管理接口和 `/settings/users` 页面：

- 分页查看未删除用户、状态和现有角色。
- 原子替换目标用户的角色集合。
- 为目标用户设置新密码，并撤销目标用户全部会话。

角色值只能来自数据库已有角色。新注册用户只有 `agent`；角色修改至少保留一个角色。系统拒绝移除或禁用最后一个有效管理员，避免失去管理入口。管理员权限必须在 Spring Security 和服务层同时校验，前端隐藏入口不构成授权。

## 前端交互

登录页保留账号密码和企业微信登录，在账号密码区域提供“登录 / 注册”模式切换。注册表单包含登录 ID、昵称、密码和确认密码；成功后直接进入系统。

账号抽屉顶部显示头像、昵称和不可编辑的登录 ID，下面分为：

- 昵称编辑。
- JPEG/PNG 头像上传、替换和删除；企业微信头像生效时明确显示其来源，上传头像作为备用保留。
- 原密码、新密码和确认密码表单。
- 现有企业微信绑定区域。

管理员的系统设置菜单增加“用户管理”。用户列表使用现有 Ant Design 表格和抽屉/弹窗模式完成角色调整与密码重置，不显示密码散列、企业微信内部 ID 或 MinIO 对象键。

所有提交按钮在请求期间禁用并显示加载状态。字段错误显示在对应控件；冲突、权限和服务失败使用现有全局消息机制，不在失败后保留明文密码。

## 错误与安全

账户领域使用统一的结构化错误类型，至少区分：

- `USERNAME_ALREADY_EXISTS`
- `ACCOUNT_VALIDATION_FAILED`
- `CURRENT_PASSWORD_INVALID`
- `PASSWORD_REUSE_NOT_ALLOWED`
- `AVATAR_INVALID`
- `USER_NOT_FOUND`
- `ROLE_INVALID`
- `LAST_ADMIN_REQUIRED`

公开注册错误不泄露密码、散列、会话或数据库信息。所有资料和头像接口需要登录；所有管理员接口需要 `ROLE_ADMIN`。上传请求、分页大小、字符串长度和图片解码尺寸均有硬上界。

## 验收标准

1. 用户可以使用合法自定义登录 ID 注册，数据库用户和唯一 `agent` 角色在同一事务中产生，注册后可直接进入系统。
2. 大小写或 NFKC 归一化后重复的用户名无法注册；并发注册不会产生重复账号或无角色账号。
3. 普通用户只能修改自己的昵称、上传头像和凭原密码修改密码，不能修改自己或他人的角色。
4. 密码修改后当前客户端获得新 token，旧 token 和其他设备 token 均失效。
5. 管理员可以查看用户、调整角色、重置密码；非管理员访问同一 API 返回 403；最后一个管理员不能被移除。
6. 非图片、超限图片、伪造 MIME 和超尺寸图片均被拒绝；合法 JPEG/PNG 可替换和读取。
7. 头像展示严格遵循企业微信头像、上传头像、昵称首字的优先级；企业微信未启用、未绑定或头像为空不会阻断账户资料查询。代开发应用的企业微信头像必须由绑定成员独立完成 `snsapi_privateinfo` OAuth2 授权：回调验证一次性 state、安装版本、企业和成员绑定，并且不得在缺少 `user_ticket` 时降级。员工资料同步读取企业微信 `avatar`，并以 `thumb_avatar` 作为上游回退；若上游未返回头像，保留已有头像并将 `wecom_parties.profile_error_code` 记录为 `WECOM_PROFILE_AVATAR_EMPTY`（姓名和头像均缺失时为 `WECOM_PROFILE_FIELDS_EMPTY`），便于区分字段缺失与请求失败。
8. 登录页、账户抽屉、顶栏和用户管理页在桌面及移动视口中无溢出，加载态、错误态和成功态可见且可操作。
9. 后端账户专项测试、前端账户专项测试、后端全量测试、前端全量测试、前端生产构建和后端 Jar 构建全部通过。
