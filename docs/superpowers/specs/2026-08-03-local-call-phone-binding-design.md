# 本地电话录音号码绑定设计

**日期：** 2026-08-03  
**状态：** 已确认  
**适用范围：** `demo/message-center-demo` 的 `LOCAL_DEV_MODE=true` 运行面

## 1. 问题

电话录音上传表单当前只允许从联系人已有的 `phone:` 身份中选择号码。本地企业微信 fixture 只生成 `wecom:` 身份，因此号码控件被禁用，无法测试“号码绑定后上传电话录音”的完整链路。

不能仅把下拉框改成任意文本并直接提交。`CallRecordService` 要求 `phonePointId` 已属于当前联系人；绕过该校验会使电话记录的身份锚点与联系人分组不一致，上传后的记录可能无法继续出现在该联系人时间线中。

## 2. 决策

仅在本地开发模式提供电话号码录入。用户输入号码后，系统先通过服务端将规范化的 `phone:` 身份绑定到当前联系人组，再使用该身份创建电话记录。

生产模式保持现有边界：只能选择联系人 owner 已提供的电话身份，不开放通过电话录音表单创建联系人身份。

## 3. Owner 与数据流

```text
本地电话录音表单
  -> 本地号码绑定 HTTP adapter
  -> UnifiedMessageStore 联系人分组 owner
  -> 刷新当前联系人投影
  -> CallRecordService 创建电话记录
```

- `UnifiedMessageStore` 拥有文件运行模式下联系人分组的写入语义，负责规范化号码、去重并持久化联系人组。
- HTTP adapter 只读取当前联系人和输入号码、检查本地模式、调用 owner 并返回更新后的联系人投影。
- 前端只负责提交号码绑定、刷新联系人并将返回的规范 `phonePointId` 放入电话录音 multipart。
- `CallRecordService` 继续执行号码属于当前联系人的最终校验，不新增绕过分支。

## 4. 合同

新增本地专用接口：

```text
POST /api/v1/local/contacts/{contactId}/phone-identities
Content-Type: application/json

{"phoneNumber":"+86 138-0000-0000"}
```

成功返回：

```json
{
  "phonePointId": "phone:8613800000000"
}
```

约束：

- 仅 `LOCAL_DEV_MODE=true` 时注册或处理该接口；其他模式返回 404，不暴露本地能力。
- `contactId` 必须解析到当前已有联系人组。
- 号码去除显示分隔字符后必须只包含 6 至 20 位数字。
- 相同规范号码重复绑定必须幂等。
- 已属于其他联系人组的号码不得被静默迁移，返回结构化冲突错误。
- 请求体、号码长度和联系人分组大小继续使用明确上界。

## 5. 界面行为

- 本地模式下，“绑定号码”区域使用可输入控件，并列出当前联系人已有号码作为建议值。
- 用户可输入带 `+`、空格或短横线的常见显示格式；服务端返回规范值后再上传。
- 已有号码仍可直接选择，不重复调用绑定接口。
- 号码为空时沿用现有“未指定号码”语义，不阻断本地录音上传。
- 绑定或上传失败时保留已选文件和表单内容，并显示服务端错误；不能出现部分上传或伪成功。
- 生产模式继续显示现有号码选择控件。

## 6. 错误与安全边界

- 非本地模式调用本地绑定接口：404。
- 联系人不存在：404。
- 号码格式无效：400。
- 号码已属于其他联系人：409。
- 联系人分组文件不可写或损坏：结构化 500，不修改内存投影。
- 号码绑定成功但录音上传失败时，号码保留在联系人资料中；绑定本身是用户明确提交的联系人资料变更，不做回滚。

## 7. 验收

- 无号码的本地 fixture 联系人可以输入 `+86 138-0000-0000` 并成功上传，multipart 中为 `phone:8613800000000`。
- 刷新页面后号码仍属于该联系人，电话卡片仍出现在同一时间线。
- 重复输入同一号码不产生重复 point。
- 非法号码、跨联系人冲突和非本地调用均被服务端拒绝。
- 已有号码选择、无号码上传、企业微信本地登录替代、电话转录与生产模式行为不回归。
- 通过聚焦单元/前端行为测试、Maven 全量测试、OpenAPI 合同测试和 `git diff --check`。

## 8. 非目标

- 不为生产环境增加通用联系人身份 CRUD。
- 不改变数据库联系人 schema 或权限模型。
- 不根据消息正文猜测电话号码。
- 不允许电话录音服务绕过联系人归属校验。
- 不修改 FunASR 协议、转录状态机或录音存储合同。
