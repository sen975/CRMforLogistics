# 助手对话归档、删除与 30 天过期设计

> 日期：2026-09-29｜状态：用户已确认
> 范围：助手对话记录的服务端归属、归档、软删除、过期和前端可见列表。

## 目标

新建对话后仍可回看旧对话；用户能主动删除不再需要的对话；连续 30 天无活动的对话自动过期，且过期对话不再进入前端列表、不能回放、恢复或继续发送。

## 唯一 owner 与数据合同

`AssistantConversationLifecycleService` 是状态机、归属和过期门禁的唯一 owner。控制器只映射认证用户与请求，前端只消费可见会话列表和服务端状态。

生命周期身份为 `(user_id, conversation_id)`，因为会话 UUID 由客户端生成且不是凭证；数据库和服务端归属始终同时限定当前用户与会话号。`assistant_conversations` 使用复合主键，历史消息以 `(user_id, conversation_id)` 回填并建立复合外键。每个用户最多一个 `ACTIVE` 会话，由部分唯一索引保证。

## 状态与转换

- `ACTIVE`：唯一当前可发送会话；新建另一会话时自动归档。
- `ARCHIVED`：仍可列出、回放；用户重新打开时成为 `ACTIVE`，原 `ACTIVE` 同时归档。
- `EXPIRED`：`last_activity_at` 早于当前时间减 30 天；不可见、不可回放、不可恢复、不可发送。
- `DELETED`：用户主动软删除；不可见、不可读取，原始消息不因该操作物理删除。

正好 30 天仍有效，超过边界后过期。请求通过 ACTIVE 门禁时立即刷新活动时间，避免长时间模型调用期间被后台扫描误过期。定时扫描按小时批量标记过期；列表、读取和发送路径也做即时过期检查，不依赖扫描及时性。

## API 与前端

助手会话列表 API 只返回 `ACTIVE` 与有消息记录的 `ARCHIVED`；服务端先执行过期扫描，再查询可见投影，历史遗留的空归档不会成为可选项。回放接口允许读取本人未过期的 ACTIVE/ARCHIVED 对话。新会话创建、归档重开和软删除分别通过生命周期服务完成。删除当前会话后，前端切换到本地新会话号但不预创建服务端空会话；删除请求失败时保留当前视图并显示错误。

前端会话选择器只消费服务端返回的可见列表，不自行推断过期时间或创建业务状态。删除按钮对当前选中的对话发起软删除。

## 验收

- 30 天整仍可活动，超过 30 天立即不能发送和回放；后台扫描使用同一 cutoff。
- 并发活动刷新赢过期竞争时不能被误判为过期。
- 新会话归档旧 ACTIVE；重新打开 ARCHIVED 会话会归档原 ACTIVE。
- 列表查询仅返回 ACTIVE/有消息的 ARCHIVED；EXPIRED/DELETED 以及空 ARCHIVED 不出现在前端。
- 删除后不再可读，消息保留为软删除记录。
- 两个用户使用相同 UUID 时，数据各自隔离，彼此仍可拥有各自 ACTIVE 会话。
- 迁移将历史消息按 `(user_id, conversation_id)` 回填，且唯一 ACTIVE 索引和复合外键成立。
