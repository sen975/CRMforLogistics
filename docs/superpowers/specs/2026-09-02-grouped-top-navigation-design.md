# 顶部导航按渠道与系统设置分组设计

## 目标

将消息中心顶部目前分散的功能入口收敛为四个平级入口：WhatsApp、企业微信、电话、系统设置。通过下拉菜单承载同一渠道或系统级功能，降低首屏视觉噪声并保持现有路由不变。

## 导航结构

```text
WhatsApp
├─ 模板 -> /templates
└─ 群发 -> /broadcasts

企业微信 -> /settings/wecom

电话
└─ 电话仓库 -> /phone-repository

系统设置
├─ 发送 -> /send
├─ Topic 仓库 -> /topic-repository
├─ 渠道设置 -> /settings/channels
├─ 账号 -> 打开账号抽屉
└─ 退出登录 -> 执行 logout
```

一级入口使用现有按钮和图标风格。WhatsApp、电话、系统设置使用 Ant Design `Dropdown`；企业微信保持直接跳转按钮，不增加多余层级。

## 权限与显示

- 群发继续受 `canBroadcast` 控制；无权限时不显示该菜单项。
- 企业微信、模板、渠道设置继续受管理员权限控制。
- 发送、Topic 仓库、电话仓库按当前登录权限显示。
- 账号和退出登录对所有已登录用户显示，并从顶栏移入系统设置菜单。

## 交互与响应式

- 桌面端一级下拉入口支持鼠标悬停打开，也支持点击和键盘焦点操作。
- 移动端改为点击打开，避免依赖 hover；顶栏保留紧凑图标/文字布局。
- 菜单项点击后使用现有 `navigate` 或现有账号抽屉状态，不改变业务页面和权限判断。
- 退出登录仍直接调用现有 `logout`，不增加新的确认流程。

## 验收标准

1. 顶栏不再平铺“发送、模板、群发、渠道设置、电话仓库、Topic 仓库、账号、退出登录”等全部入口。
2. 四个一级入口按上述结构显示，企业微信仍可直接进入管理页。
3. 管理员和非管理员看到的菜单符合现有权限规则。
4. 菜单项跳转、账号抽屉、退出登录行为与改动前一致。
5. 桌面端 hover/键盘和移动端 click 均能打开对应菜单。
6. `AppLayout` 定向测试和前端生产构建通过。
