一、口径（三层账，缺一层就有盲区）

层怎么取能抓什么抓不到什么
前端声明面解析 endpoints.ts 的 client.<verb>(path)写接口也能覆盖（不需要真发出去）服务端到底有没有
后端路由表解析 @RestController 上全部 Mapping 注解源码真值跑着的进程是不是这份
活体 OPTIONS对每条路径发 OPTIONS，读状态码 + Allow进程陈旧 / 路径未注册 / 动词不匹配业务逻辑对不对
为什么用 OPTIONS 当探针：Spring 的 FrameworkServlet.doOptions 只查 handler mapping，不会进入任何 @RequestMapping 方法 —— 所以它能安全地探到每一条路径（包括写接口）而不产生任何副作用：未注册路径返 404，已注册返 200 且带 Allow 动词表。
活体状态码分布（「通过」不等于「全 200」）：
OPTIONS（190 行）：200 × 156、404 × 34
只读实测（72 条）：200 × 26、400 × 9、404 × 34、410 × 1、500 × 2
只读 4xx 是业务 / 参数 / 权限拒绝，说明路由是通的（样本 id 是随机 UUID，查不到很正常）；只有 5xx 才是真故障。
